= Skills

Los *skills* de OpenCode son instrucciones versionadas en archivos `SKILL.md` que OpenCode carga bajo demanda. Viven en el pod en `$HOME/.config/opencode/skills/<nombre>/SKILL.md`, y el despliegue de OpenCode (módulo 5) los copia del repo del workshop al arrancar.

En este módulo analizamos y ejecutamos el skill `enable-observability`: habilita el stack de observabilidad de MaaS para ver las *métricas de tokens* que OpenCode está generando con este mismo stack (usage logging + dashboards). Analizar el skill es, a la vez, la excusa para contar cómo se implementa cada una de las piezas del stack.

== Qué son los skills

Un skill es un `SKILL.md` con dos partes:

* `name`: el identificador con el que lo invoca OpenCode.
* `description`: lo que OpenCode usa para decidir *cuándo* activar el skill.
* El cuerpo: define *qué hace* (instrucciones paso a paso).

[source,markdown]
----
---
name: enable-observability
description: Habilita la observabilidad de MaaS en este cluster
  OpenShift AI (Tempo, OpenTelemetry, Cluster Observability Operator,
  Loki, MinIO + LokiStack y usage logging) para ver los tokens
  generados por API key. Usar cuando el usuario pida habilitar
  observabilidad o ver el uso de tokens.
---

(instrucciones paso a paso...)
----

== Skills instalados

El despliegue de OpenCode (módulo 5) copia los skills del repo a `~/.config/opencode/skills/` al arrancar (el entrypoint del pod lo hace; sobreviven a los restarts). Verificalo:

[source,bash]
----
oc -n opencode exec deploy/opencode-agent -- ls /tmp/.config/opencode/skills/
----

CAUTION: En el pod `~` es `/tmp`: si copias un skill a mano, usa la ruta explícita `/tmp/.config/opencode/skills/`, porque el `~` lo expande el shell de tu web terminal a `/home/user`.

# Enable MaaS observability

El stack se instala con el script del repo `rhoai-showroom`: clonalo si no existe, entra al directorio y ejecuta el script desde ahí. Al final verifica el estado y sale del repo con `cd ..`.

## 1. Clonar el repo

```sh
[ -d rhoai-showroom ] || git clone https://github.com/pkstaz/rhoai-showroom.git
cd rhoai-showroom
```

## 2. Stack de observabilidad

```sh
bash manifests/apply-maas-observability.sh
```

El script instala los operadores (Tempo, OpenTelemetry, Cluster Observability Operator, Loki), configura el monitoreo del DSCI (`monitoring`), enciende la telemetría del gateway (`maastenantconfig`), despliega MinIO + LokiStack y enciende `usageLogging`.

Puede tardar 10–20 minutos: espera cada CSV en `Succeeded`, LokiStack `Ready` y el patch de `usageLogging`. Muestra el progreso mientras corre y no lo interrumpas. Si se corta en un `oc wait` (`no matching resources found`), vuelve a lanzarlo: es idempotente.

## 3. Corregir la imagen de MinIO

Las imágenes `quay.io/minio/minio` y `docker.io/minio/minio` son privadas (MinIO quitó las públicas), así que el script deja el pod de MinIO en `ImagePullBackOff` y el job `minio-create-bucket` falla. Parchea el deployment con el mirror de Red Hat:

```sh
oc -n redhat-ods-monitoring set image deploy/minio minio=quay.io/rh-aiservices-bu/minio:RELEASE.2025-09-07T16-13-09Z
oc -n redhat-ods-monitoring wait --for=condition=available deploy/minio --timeout=180s
```

Después recrea el job `minio-create-bucket` (los jobs son inmutables): exportalo, quitá el selector/uid viejos, cambiále la imagen y re-aplicalo:

```sh
oc get job minio-create-bucket -n redhat-ods-monitoring -o json \
  | jq 'del(.status, .metadata.uid, .metadata.resourceVersion, .metadata.creationTimestamp, .metadata.generation, .metadata.managedFields, .metadata.ownerReferences, .spec.selector, .spec.template.metadata.labels)' \
  | sed 's|quay.io/minio/mc:latest|quay.io/rh-aiservices-bu/mc:latest|' > /tmp/job2.yaml
oc delete job minio-create-bucket -n redhat-ods-monitoring --grace-period=0 --force
oc apply -f /tmp/job2.yaml
```

El job debe quedar `Complete` (crea el bucket `loki` que la LokiStack necesita para escribir). Verifica el estado final con `oc get pods -n redhat-ods-monitoring | grep minio`.

## Verificación final

```sh
oc get csv -n openshift-tempo-operator | grep tempo
oc get csv -n openshift-opentelemetry-operator | grep opentelemetry
oc get csv -n openshift-cluster-observability-operator | grep cluster-observability
oc get csv -n openshift-operators-redhat | grep loki
oc get dsci default-dsci -o jsonpath='{.spec.monitoring.metrics}'; echo
oc get maastenantconfig default-tenant -n models-as-a-service -o jsonpath='{.spec.telemetry}'; echo
oc get lokistack usage -n redhat-ods-monitoring
oc get configs.maas.opendatahub.io default -o jsonpath='{.spec.usageLogging}'; echo
```

CSVs en `Succeeded`, `metrics` con replicas/storage, telemetría `enabled: true` y `usageLogging` `true`.

## Dónde ver los tokens

- RHOAI → *Observe & monitor* → *Dashboard* → Usage (tokens / requests por subscription)
- RHOAI → *Models as a Service* → API keys / uso por key

== Instalar todo el módulo de una vez

Como alternativa al skill, desde la terminal: el repo https://github.com/pkstaz/rhoai-showroom[rhoai-showroom] trae el instalador del stack de observabilidad. Clonalo (si no lo hiciste en el módulo 6), entrá al repo y ejecutá el script:

[source,bash]
----
git clone https://github.com/pkstaz/rhoai-showroom.git
cd rhoai-showroom
bash manifests/apply-maas-observability.sh
cd ..
----

El script instala los operadores (Tempo, OpenTelemetry, Cluster Observability Operator, Loki), configura el monitoreo del DSCI, enciende la telemetría del gateway, despliega MinIO + LokiStack y enciende `usageLogging`. Puede tardar 10–20 minutos y es idempotente: se puede re-ejecutar.

NOTE: Si el pod de MinIO queda en `ImagePullBackOff` (las imágenes `quay.io/minio/*` son privadas), parcheá la imagen con el mirror de Red Hat y recreá el job del bucket — los comandos exactos están en el paso 3 del colapsable del skill de arriba.

== Cómo se implementa cada pieza

[cols="1,2"]
|===
|Componente |Detalle

|Tempo / OTEL
|Trazas del gateway y del stack de inferencia.

|Cluster Observability Operator
|Dashboards (Perses) de uso.

|Loki + MinIO + usage logging
|Registro de uso por API key: tokens de entrada/salida por request.
|===

Los waits largos son los operadores (varios minutos cada uno).

== Ver los tokens

. Generá tráfico con OpenCode (preguntas de código).
. Abrí *RHOAI → Observe & monitor → Dashboards* y busca los dashboards de uso/usage.
. En *RHOAI → Models as a Service → API keys / usage*, verifica el consumo de la key `opencode-workshop`.

== Verificar

[source,bash]
----
oc get configs.maas.opendatahub.io default -o jsonpath='{.spec.usageLogging}'; echo
oc get lokistack usage -n redhat-ods-monitoring
oc get persesdashboard -n redhat-ods-monitoring
----

== Verificación final

Checklist end-to-end del stack que dejaste funcionando: OpenCode → MaaS → observabilidad de tokens.

[cols="1,3"]
|===
|Componente |Verificación

|Modelo base detenido
|`oc get isvc llama-32-3b-instruct -n my-first-model -o jsonpath='{.status.conditions[?(@.type=="Stopped")].status}'` = `True`; GPU libre.

|Modelo L4
|`oc get llminferenceservice qwen3-14b-awq -n my-first-model` en `Ready`.

|OpenCode
|`oc get route opencode-agent -n opencode` responde; OpenCode conectado con el modelo MaaS.

|Skills
|`ls ~/.config/opencode/skills/` (en el pod) lista los skills instalados (`enable-observability`).

|MaaS
|`oc get gateway maas-default-gateway -n openshift-ingress` en `Programmed`; `maas-api` / `maas-controller` en `Running`.

|Modelo publicado
|`oc get maasmodelref qwen3-14b-awq -n my-first-model` en `Ready`; visible en *RHOAI → Models as a Service*.

|Observabilidad
|`oc get configs.maas.opendatahub.io default -o jsonpath='{.spec.usageLogging}'` = `true`; dashboards de uso en RHOAI.
|===

E2E completo:

. En OpenCode, genera varias respuestas de código.
. Abrí *RHOAI → Models as a Service* → uso de la API key `opencode-workshop`: deben aparecer los requests y los tokens.
. Abrí *RHOAI → Observe & monitor → Dashboards*: dashboards de uso con los tokens de entrada/salida.

CAUTION: Si el uso no aparece, verifica que el `LLMInferenceService` tenga `--enable-force-include-usage` (módulo 4) y que `usageLogging` esté encendido (este módulo).
