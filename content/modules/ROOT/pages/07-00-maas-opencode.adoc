= OpenCode + modelo MaaS

Con MaaS encendido, publicamos `{l4-model}` en Models as a Service y reconfiguramos OpenCode para consumirlo vía MaaS (gateway + API key), en lugar de la ruta directa del módulo 3.

== 1. Publicar el modelo en MaaS

Tres pasos, desde la raíz del repo:

[source,bash]
----
# Adjuntar el modelo al gateway de MaaS (hasta ahora tenía el suyo)
oc patch llminferenceservice qwen3-14b-awq -n my-first-model --type merge -p '
{"spec":{"router":{"gateway":{"refs":[{"name":"maas-default-gateway","namespace":"openshift-ingress"}]}}}}'

# Auth real de MaaS en la ruta del modelo (llm-d pone auth anónima que pisa
# la auth del gateway: sin esto no hay validación de key, cuotas ni métricas)
oc -n my-first-model annotate llminferenceservice qwen3-14b-awq \
  security.opendatahub.io/enable-auth=true --overwrite

# Referencia en MaaS
oc apply -f manifests/maas/maas-model-ref.yaml

# Auth policy + subscription (cuotas de tokens)
oc apply -f manifests/maas/subscription.yaml
----

Espera que el `MaaSModelRef` pase a `Ready`:

[source,bash]
----
oc get maasmodelref qwen3-14b-awq -n my-first-model
----

== 2. Crear API key

Desde la UI: *RHOAI → Models as a Service → API keys* → crea una key para tu usuario.

O por API, con tu token de OpenShift:

[source,bash]
----
TOKEN=$(oc whoami -t)
MAAS_HOST="maas.$(oc get ingresses.config/cluster -o jsonpath='{.spec.domain}')"
API_KEY=$(curl -sk -X POST "https://${MAAS_HOST}/maas-api/v1/api-keys" \
  -H "Authorization: Bearer ${TOKEN}" -H "Content-Type: application/json" \
  -d '{"name":"opencode-workshop"}' | jq -r '.key')
echo "${API_KEY}" # guarda esta key
----

`API_KEY` queda seteada para el paso siguiente (misma sesión de terminal).

== 3. Reconfigurar OpenCode con el modelo MaaS

Actualizá el `ConfigMap/opencode-config` del pod con el baseURL de MaaS y la API key:

[source,bash]
----
MAAS_HOST="maas.$(oc get ingresses.config/cluster -o jsonpath='{.spec.domain}')"
# si cambiaste de sesión: API_KEY=<la-api-key>
oc -n opencode create configmap opencode-config \
  --from-file=opencode.jsonc=<(cat <<EOF
{
  "\$schema": "https://opencode.ai/config.json",
  "provider": {
    "maas": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "MaaS (Qwen3-14B-AWQ)",
      "options": {
        "baseURL": "https://${MAAS_HOST}/my-first-model/qwen3-14b-awq/v1",
        "apiKey": "${API_KEY}"
      },
      "models": {
        "qwen3-14b-awq": {
          "limit": {
            "context": 32768,
            "output": 8192
          }
        }
      }
    }
  },
  "model": "maas/qwen3-14b-awq"
}
EOF
) --dry-run=client -o yaml | oc apply -f -
oc -n opencode rollout restart deploy/opencode-agent
----

NOTE: El `baseURL` usa la *ruta por path del modelo* (`/my-first-model/qwen3-14b-awq/v1`). Si usas `/v1` a secas, el gateway devuelve `404 Not Found`: el HTTPRoute solo matchea `/v1/chat/completions` con el header `X-Gateway-Model-Name`, y en este sandbox la AuthPolicy de llm-d (que se recrea sola) entra en conflicto con la de MaaS y evita esa inyección. La ruta por path siempre matchea.

== 4. Probar

En OpenCode, pregúntale algo de código. La respuesta ahora pasa por el *gateway de MaaS* (con auth y cuotas). Puedes ver la key activa y su uso en *RHOAI → Models as a Service*.

== Verificar

[source,bash]
----
oc get maasmodelref -n my-first-model
oc get maassubscription,maasauthpolicy -A
----
