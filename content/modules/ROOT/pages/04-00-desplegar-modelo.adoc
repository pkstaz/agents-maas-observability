= Desplegar modelo

`{l4-model}` es un modelo de coding cuantizado (AWQ INT4, ~5.5 GB) que performa muy bien en una *L4*: rápido, con contexto suficiente para OpenCode. Lo servimos con *llm-d* vía `LLMInferenceService` y al final lo publicamos en *MaaS*.

Requisitos: nodo L4 disponible (módulo 1), MaaS habilitado (módulo 3).
Manifiesto: `manifests/llminferenceservice-qwen3-14b-awq.yaml` del repo del workshop.

== Detener modelo base

El cluster trae `{base-model}` pre-configurado (KServe, proyecto `my-first-model`). Lo *detenemos* para liberar la L4 para el modelo Qwen (queda detenido, no eliminado, listo para reactivarse).

Es un stop nativo de KServe: anotación `serving.kserve.io/stop=true` (lo mismo que el botón *Stop* del dashboard). El ISVC pasa a `Stopped=True`, el pod termina y la GPU queda libre.

[source,bash]
----
oc annotate isvc llama-32-3b-instruct -n my-first-model serving.kserve.io/stop="true"
----

Esperá que el pod termine y que la GPU quede libre:

[source,bash]
----
oc get isvc llama-32-3b-instruct -n my-first-model -o jsonpath='{.status.conditions[?(@.type=="Stopped")].status}'; echo
oc get pods -n my-first-model
oc get nodes -o json | jq -r '.items[].status.allocatable | select(."nvidia.com/gpu" != null) | ."nvidia.com/gpu"'
----

`Stopped = True` y sin pods del modelo. En *RHOAI → Model deployments*: `{base-model}` aparece detenido.

NOTE: Para reactivar el modelo base después del workshop: `oc annotate isvc llama-32-3b-instruct -n my-first-model serving.kserve.io/stop="false"` (o `serving.kserve.io/stop-` para quitar la anotación).

== Qué crea el manifiesto

[cols="1,2"]
|===
|Recurso |Detalle

|Namespace `my-first-model`
|El proyecto del modelo (el mismo del modelo base, ya permitido por el gateway del cluster). El apply asegura los labels `opendatahub.io/dashboard=true` y `maas.opendatahub.io/gateway-access=true` (este último lo usará MaaS al publicar el modelo).

|`LLMInferenceService/qwen3-14b-awq`
|llm-d + vLLM CUDA (RHAI Early Access), `max-model-len=8192`, 1 GPU, `nodeSelector` `NVIDIA-L4`, `--enable-force-include-usage` (necesario para el uso/tokens en MaaS). El pod sirve *HTTPS*: monta el cert en `/var/run/kserve/tls` que el gateway llm-d usa para re-encriptar.

NOTE: Si el log del pod muestra `WARNING: Invalid HTTP request received` en bucle, vLLM está sirviendo HTTP plano y el gateway le envía TLS. Faltan los flags `--ssl-certfile/--ssl-keyfile/--enable-ssl-refresh` en el manifiesto.

|`Connection/qwen3-14b-awq`
|Secret tipo `uri-v1` con el URI del modelo en HF + anotación `opendatahub.io/connections` en el deploy: el wizard del dashboard muestra el *Model location* ("Where is the model currently located?") pre-cargado al editar.

|Hardware profile
|Anotaciones `opendatahub.io/hardware-profile-name/namespace` apuntando a `gpu-profile` (en `redhat-ods-applications`): el deploy queda asociado al profile en el dashboard. Recursos dentro del rango del profile (memoria 12Gi/16Gi, CPU 4/8).
|===

== Clonar el repo

Antes de ejecutar los comandos, clona el repo (necesitas el archivo del manifiesto):

[source,bash]
----
git clone https://github.com/pkstaz/agents-maas-observability.git
cd agents-maas-observability
----

== Instalar por terminal

Desde la raíz del repo:

[source,bash]
----
oc apply -f manifests/llminferenceservice-qwen3-14b-awq.yaml
----

== Esperar Ready

[source,bash]
----
oc wait --for=condition=Ready llminferenceservice/qwen3-14b-awq -n my-first-model --timeout=1200s
oc get pods -n my-first-model
----

La primera vez descarga el modelo de Hugging Face: puede tardar varios minutos.

== Probar inferencia

Saca la URL del modelo (la expone el gateway del cluster) y prueba un chat completion:

[source,bash]
----
URL=$(oc get llminferenceservice qwen3-14b-awq -n my-first-model -o jsonpath='{.status.url}')
echo "${URL}/v1"
curl -sk ${URL}/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen3-14b-awq","messages":[{"role":"user","content":"Escribe un hola mundo en Python"}],"max_tokens":128}' | jq
----

== Publicar el modelo en MaaS

Con MaaS encendido (módulo 3), publicamos `{l4-model}` en Models as a Service: lo adjuntamos al gateway de MaaS y creamos su referencia. Desde la raíz del repo:

[source,bash]
----
# Adjuntar el modelo al gateway de MaaS (hasta ahora tenía el suyo)
oc patch llminferenceservice qwen3-14b-awq -n my-first-model --type merge -p '
{"spec":{"router":{"gateway":{"refs":[{"name":"maas-default-gateway","namespace":"openshift-ingress"}]}}}}'

# Auth real de MaaS en la ruta del modelo (llm-d pone auth anónima que pisa
# la auth del gateway: sin esto no hay validación de key, cuotas ni métricas)
oc -n my-first-model annotate llminferenceservice qwen3-14b-awq \
  security.opendatahub.io/enable-auth=true --overwrite

# Referencia en MaaS
oc apply -f manifests/maas/maas-model-ref.yaml

# Auth policy + subscription (cuotas de tokens)
oc apply -f manifests/maas/subscription.yaml
----

Espera que el `MaaSModelRef` pase a `Ready`:

[source,bash]
----
oc get maasmodelref qwen3-14b-awq -n my-first-model
----

== Verificar en UI

* *RHOAI → Model deployments*: `qwen3-14b-awq` en `Ready`.
* *RHOAI → Models as a Service*: `qwen3-14b-awq` aparece publicado.
